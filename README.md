# Аким на 5 часов

Интерактивный симулятор распределения виртуального бюджета между пятью направлениями развития условных районов Астаны. Проект команды **BEZBAB** для HackAlem AI.

## Быстрый запуск

Нужен Python 3. Установка пакетов и API-ключ не требуются.

```bash
python server.py
```

Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000). На Windows при необходимости используйте `py server.py`. Небольшой сервер нужен, чтобы браузер правильно загружал JavaScript-модули `.mjs`. Если порт 8000 занят: `python server.py --port 8001`.

> Открывать `index.html` двойным кликом не следует: браузеры ограничивают загрузку JavaScript-модулей через `file://`.

## Основной сценарий

1. Посмотрите исходные показатели трёх условных районов.
2. Выберите по одному мероприятию и району для транспорта, озеленения, социальной инфраструктуры, безопасности и городского сервиса. После выбора района на карточках мероприятий появляется ожидаемый прямой эффект (`≈ +N п.`), а в списке районов — их текущий показатель.
3. Система считает общую стоимость и не принимает мероприятие, которое превысит 100 единиц бюджета; недоступные по бюджету варианты приглушены, подсказка показывает, сколько не хватает.
4. Когда выбраны все пять решений, в панели бюджета сразу виден прогноз Score.
5. Нажмите «Рассчитать сценарий»: увидите Astana Quality of Life Score, изменение разрыва между районами, сильные стороны, риски (в том числе районы без единого решения), вклад каждого решения (прямой и побочный эффект, пунктов на 10 ед.) и прирост каждого показателя по районам.
6. Алгоритмический советник покажет конкретную замену одного решения, а также переберёт допустимые комбинации и предложит сценарий с наибольшим Score по правилам этой модели.
7. Сохраните до шести сценариев в браузере: их можно сравнить с текущим (Score, стоимость и конкретные изменённые решения), снова открыть или удалить.
8. «Скопировать ссылку» кладёт сценарий в адрес страницы (`#s=...`). На опубликованном сайте такая ссылка открывает те же решения и Score. При локальном запуске получателю тоже нужно запустить проект и открыть этот адрес на своём `localhost` (с тем же портом) либо перенести часть ссылки после `#` в адрес своего сервера.

Все пользователи стартуют с **одинакового бюджета 100 единиц** и **одинаковых синтетических данных** из `data.mjs`. Персональные данные не используются.

## Как устроена модель

- Каждый показатель имеет шкалу от 0 до 100, где больше — лучше.
- Каждое мероприятие имеет фиксированную стоимость и базовый эффект. Фактический эффект выше в районе с более низким исходным показателем: `эффект = базовый эффект × (0.75 + (100 − исходное значение) / 200)`, с ограничением результата до 100.
- Помимо основного направления, каждое мероприятие даёт небольшой побочный эффект: транспорт → сервис (12%), озеленение → безопасность (8%), социальная инфраструктура → безопасность (10%), безопасность → транспорт (7%), сервис → социальная инфраструктура (8%).
- Для каждого района берётся среднее пяти показателей. Общегородское значение — среднее районных оценок с весом по синтетическому населению районов.
- Если разрыв между районными оценками по сравнению с исходным состоянием вырос, применяется штраф: `0.18 × прирост разрыва`.
- Итоговый **Score** — общегородское значение после решений минус штраф за неравномерность, ограниченное интервалом 0–100.
- Советник полным перебором проверяет варианты: три мероприятия × три района для каждого из пяти направлений. Из допустимых по бюджету выбирает максимальный Score. При равенстве выбирает более дешёвый сценарий.
- Отдельный совет проверяет все замены **одного** решения и выбирает наибольшее допустимое улучшение, чтобы рекомендацию можно было сразу понять и применить.

`engine.mjs` содержит расчёт и проверку, `data.mjs` — синтетические исходные данные и мероприятия, `main.mjs` — интерфейс. Расчёт детерминирован: одинаковые решения всегда дают одинаковый результат.

### Что здесь называется AI

Это **объяснимая экспертная модель с поиском оптимального сценария**, а не большая языковая модель. Она автоматически оценивает решения, находит слабое место, объясняет преимущества и риски и ищет лучший вариант по заданной функции качества. Внешний LLM или API-ключ не нужны. Числа являются учебной моделью и **не являются прогнозом для реальной Астаны**.

## Проверка

Если установлен Node.js 20 или новее:

```bash
node --test
```

Тесты проверяют единый бюджет, обязательность пяти решений, реакцию Score на изменения, поиск допустимого улучшенного сценария, кодирование сценария в ссылку, подсказку эффекта и предупреждение о районах без решений.

## Ограничения и развитие

- Данные и эффекты синтетические; для реального управления нужны открытые городские данные, калибровка модели и экспертная проверка причинных связей.
- Сценарии хранятся только в `localStorage` данного браузера. Обмениваться ими можно ссылкой `#s=...`, но общей таблицы результатов нет — для неё нужен сервер.
- Функция качества поощряет вложения в самый отстающий район, поэтому математически лучший сценарий может направить все пять решений в один район. Анализ отмечает это как риск; при желании можно добавить в Score явный штраф за районы без решений.
- При наличии API-ключа можно подключить LLM для более свободного текстового объяснения, сохранив расчёт Score на сервере или в проверяемой модели. Секретный ключ нельзя размещать в браузерном коде или коммитить в репозиторий.
