# Аким на 5 часов — BEZ BAB

React + TypeScript + Vite, Tailwind CSS v4, lucide-react и Three.js. Симулятор использует предоставленный файл «Датасет районов.docx»: 5 районов, 10 показателей, 14 мероприятий, 100 условных единиц бюджета. Это условная модель, не реальные статистические данные Астаны.

## Запуск

Нужен Node.js 22.12+ либо совместимая более новая версия.

```sh
cd frontend
npm install
npm run dev
```

Откройте http://localhost:5173. Команды: `npm run build`, `npm run lint`, `npm test`.

## Правила

- Ровно 5 разных мер, каждая максимум один раз, не более 2 мер одного направления.
- Бюджет 100 у. е.; остаток не даёт бонуса.
- Для районной меры нужно выбрать район; городская действует во всех пяти районах без указания района.
- M1 и M3 несовместимы независимо от района.
- M4 + M7 и M5 + M13 несовместимы только в одном районе.
- Снять выбор можно кнопкой «Убрать» или крестиком в списке. Изменение района переносит выбранную меру, сохраняя её стоимость.
- Кнопки недопустимых добавлений отключены с объяснением причины. Невалидному и незавершённому набору итоговый Score не присваивается.

## Модель

Горизонт H = 8 кварталов. Эффект каждой меры умножается на `(8 − lag) / 8`. Затем прибавляются фиксированные синергии, после чего каждый показатель ограничивается диапазоном 0–100. Промежуточные значения не округляются.

Синергии: M1 + M2 → T1 +2 в районе M1; M10 + M12 → B1 +2 в районе M10; M5 + M6 → E2 +2 в районе M5. Лаг не уменьшает бонус синергии.

Оценка района D — сумма 10 показателей с весами из датасета. D_avg — средняя оценка районов по долям населения. Формула:

`Score = 0.7 × D_avg + 0.3 × min(D) − N_crit`

N_crit — число пар «район × показатель» со значением строго ниже 40. Итог округляется до двух знаков только для представления. Пять укрупнённых полосок направлений — взвешенные средние соответствующих пар показателей; полные значения доступны в блоке «Все 10 показателей».

Базовый D_avg = 56.8624, два критических значения в Нуре, базовый Score = **52.56**. Набор M7/Нура + M8/Нура + M10/Нура + M12/город + M5/Сарыарка стоит **95** и даёт **56.54**, что соответствует ≈56.5 в документе.

Численность населения в людях документ не задаёт: в интерфейсе используются доли 27%, 24%, 20%, 13% и 16%. Подробности источника — `DATASET.md`.

## 3D-город

Вращайте мышью, приближайте колесом/жестом или кнопками. Кнопки районов приближают камеру. Переключатель «до / после» сравнивает одинаковый ракурс; есть день/вечер и пауза движения. Все 14 мер имеют своё представление. Районная мера появляется в выбранном районе; городская — во всех пяти. География схематическая.

Three.js загружается при открытии экрана. Нужен WebGL 2; при его недоступности или потере контекста показана SVG-карта, выбор и расчёт продолжают работать. Системная настройка уменьшенного движения отключает анимацию по умолчанию.

## Сохранение

Новая схема использует localStorage `akim-scenario-dataset-v2` и сохраняет только ID и район. Старый `akim-scenario-v1` остаётся в браузере, но не переносится автоматически: его меры, цены и правила несовместимы с новым датасетом. При восстановлении применяются текущий каталог и валидатор; некорректный набор отвергается целиком.

## AI: только объяснение готового расчёта

Без `VITE_ANALYSIS_URL` используется локальное объяснение. Для AI скопируйте `.env.example` в `.env.local`, укажите backend URL и перезапустите Vite. Ключ провайдера хранится на backend, не в `VITE_*`.

Новый контракт запроса POST JSON:

```ts
{
  datasetVersion: 'districts-2026-v2',
  horizon: 8,
  budget: { total: 100, spent: number, currency: string },
  districts: District[],
  decisions: { id: string, district?: string }[],
  calculation: {
    valid: true, score: number,
    projected: District[],
    breakdown: { score: number, average: number, weakest: object, critical: object[], districtScores: object[] },
    deltas: object[], contributions: object[], synergies: object[], errors: []
  },
  instructions: string
}
```

Backend возвращает `summary: string`, `strengths: string[]`, `risks: string[]`, `recommendations: string[]`. Числовой Score всегда берётся из детерминированного расчёта; поле `score` от AI игнорируется. Backend должен самостоятельно проверять решения и пересчитывать значения перед передачей их LLM. На фронтенде лимит запроса — 30 секунд; при ошибке доступно локальное объяснение. CORS настраивается на backend.

## Проверки

`npm test` проверяет исходные значения, пример документа, 10 010 комбинаций наборов и целевых районов, 120 перестановок примера, область действия, лаги, синергии, отрицательный эффект M11, строгий порог 40, несовместимости, бюджет, максимум две меры, перенос/отмену, восстановление, неизменность исходных данных и запрет AI менять Score. Проверяется размещение всех 14 мер в 3D. Браузерная проверка охватывает пример, перенос меры, блокировки, до/после и мобильную версию.

## Основные файлы

- `src/data/mockCityData.ts` — значения и определения показателей из документа, доли населения, бюджет.
- `src/data/initiatives.ts` — 14 мер, эффекты, лаги, синергии.
- `src/lib/simulation.ts` — валидатор, расчёт, сохранение, адаптер AI.
- `src/components/DecisionPanel.tsx` — единый выбор мер для обычного и 3D-экрана.
- `src/components/DatasetDetails.tsx` — 10 показателей и разложение Score.
- `src/scene/CityWorld.ts`, `cityPlan.ts` — 3D-сцена и размещение мер.
- `scripts/test-simulation.mjs` — регрессионные проверки модели.
